Create a database for your server

Many plugins, FiveM frameworks and bots store their data in MySQL. Every plugged.host server can have up to five MariaDB databases, which speak the same protocol.

Updated 12 October 2026

Create one

  1. Open your server's menu, expand More and choose Databases.
  2. Choose Create Database.
  3. Pick the Database Host and type a Database Name. The panel puts a short prefix in front of it, so the full name looks like s123_mydata.
  4. Leave Connections From on % to allow connections from anywhere with the password, or enter an address to allow only that one.

Find the credentials

Open the database to see its Host, Database, Username and Password, plus a ready-made JDBC Connection String for Java plugins. The password can be rotated from the same place if it ever leaks; update your configuration afterwards.

The Host is a name and a port separated by a colon. Some tools take it in one field; others want the part before the colon as the host and the number after it as the port. The database runs on its own machine, not inside your server, so localhost or 127.0.0.1 won't work.

Connect it

A Minecraft plugin

Plugins such as LuckPerms and CoreProtect ask for the same fields in their configuration file:

storage-method: mysql
data:
  address: host-and-port-from-the-panel
  database: s123_mydata
  username: u123_AbCdEf
  password: the-password

The field names differ a little from plugin to plugin; the values are always the four from the panel. Restart the server after editing.

FiveM with txAdmin

Create the database before you run a recipe in txAdmin, then give txAdmin the host, name, username and password when it asks. See the FiveM guide.

A bot

Put the credentials in your .env file next to the token, never in your code:

DB_HOST=host-name-from-the-panel
DB_PORT=port-from-the-panel
DB_NAME=s123_mydata
DB_USER=u123_AbCdEf
DB_PASSWORD=the-password

Then use a MySQL client library, such as mysql2 in Node.js or aiomysql in Python, with those values.

Good to know

  • Backups of your server don't include its databases. Most plugins and frameworks can export their data; do that before big changes.
  • Deleting a database deletes its data for good.
  • Subusers only see the password if you give them the permission to view it.
