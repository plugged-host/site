Host a Discord bot with Node.js

Run a discord.js bot, or any other Node.js program, on plugged.host so it keeps running without your own computer.

Updated 12 October 2026

Before you start

  • A bot application in the Discord Developer Portal, and its token (your application › Bot › Reset Token). Turn on the privileged intents your code asks for on the same page, such as Message Content.
  • Your bot's code, with a package.json that lists its dependencies, for example discord.js.
  • A plugged.host account. You sign in with a noprofit.space account; the first sign-in creates it.

1. Create the server

  1. Open the panel at panel.plugged.host and choose Create server.
  2. Give it a name and pick node.js generic under Game.
  3. Pick a location, then a plan. Most bots are happy on Starter (one CPU thread, 2 GB of memory, 10 GB of disk); a bot that plays music or serves many guilds may want more memory.
  4. Choose Deploy server. The panel installs the runtime and opens the server's console.

2. Put your code on the server

The simplest way is the Files page. Upload your project, or upload it as a .zip and unpack it on the server. Leave node_modules out: the server installs your dependencies itself every time it starts. For many files, connect over SFTP instead.

If your bot lives in a Git repository, the server can clone it. On the server's Startup page, fill in Git Repo Address and Install Branch; for a private repository add Git Username and a Git Access Token (on GitHub, a fine-grained token with read-only access to that one repository). The repository is cloned when the server is installed, into an empty folder, so set these on a fresh server and reinstall it from Settings. Set Auto Update to 1 and the server runs git pull before every start, so a restart deploys your latest commit.

3. Keep the token out of your code

Anyone who has your token controls your bot, so it should not sit in your source files or in Git. Create a file named .env next to your code on the Files page:

DISCORD_TOKEN=paste-your-token-here

Add dotenv to the dependencies in package.json, then load it on the first line of your main file and read the token from the environment:

require('dotenv').config();
const { Client, GatewayIntentBits } = require('discord.js');

const client = new Client({ intents: [GatewayIntentBits.Guilds] });
client.once('ready', () => console.log(`Logged in as ${client.user.tag}`));
client.login(process.env.DISCORD_TOKEN);

With ES modules, write import 'dotenv/config'; instead of the first line. Recent Node.js versions can also read the file without a package: call process.loadEnvFile() before you use the token.

Add .env to your .gitignore. If a token ever leaks, reset it in the Developer Portal right away and paste the new one into .env.

4. Tell the server what to run

On the Startup page:

  • Main file is the file the server starts, index.js by default. Change it if your entry point is called something else, such as bot.js or src/index.ts (up to 16 characters). TypeScript files run directly, without a build step.
  • Docker Image picks the Node.js version. Use the one your bot is developed on; discord.js needs a recent one.
  • Additional Node packages installs extra packages, separated by spaces, on every start. You normally don't need it: list your dependencies in package.json instead.

5. Start it

Press Start. On every start the server runs npm install for your package.json, then starts the main file. Watch the console: with the example above you will see Logged in as YourBot#1234, and the bot shows as online in Discord.

Idle servers

Free capacity is shared, so a server nobody has used for two days is stopped to make room. "Used" means activity in the panel: starting or stopping it, the console, files, backups, and anything your subusers or neo do there. Start it again from the panel and it carries on as before. If it stays idle for longer, it can be moved into hibernation; its Console then offers Restore server, which brings it back for a few tokens.

When it doesn't start

Cannot find module 'discord.js'
The package is missing from package.json, or your code is in a subfolder and package.json is not in the server's top folder. Move the files up a level or fix the dependency list.
An invalid token was provided
The token was reset, or .env was not loaded. Check that the file is called exactly .env, sits next to your main file, and that dotenv is loaded before client.login.
Used disallowed intents
Your code asks for a privileged intent that is switched off. Turn it on under Bot in the Developer Portal.
The console stops right after starting
Check that Main file points at a file that exists. Or open neo in the panel and ask it to find out why the bot won't start; it reads the console and the files and can fix most of these for you.
