Host a Discord bot with Python

Run a discord.py bot, or any other Python program, on plugged.host so it keeps running without your own computer.

Updated 12 October 2026

Before you start

  • A bot application in the Discord Developer Portal, and its token (your application › Bot › Reset Token). Turn on the privileged intents your code needs on the same page, such as Message Content.
  • Your bot's code and a requirements.txt that lists its packages, for example discord.py.
  • A plugged.host account. You sign in with a noprofit.space account; the first sign-in creates it.

1. Create the server

  1. Open the panel at panel.plugged.host and choose Create server.
  2. Give it a name and pick python generic under Game.
  3. Pick a location, then a plan. Starter (one CPU thread, 2 GB of memory, 10 GB of disk) runs most bots comfortably.
  4. Choose Deploy server. The panel installs Python and opens the server's console.

2. Put your code on the server

Upload your project on the Files page, or as a .zip that you unpack on the server. Leave virtual environments such as venv/ out: the server installs your packages itself. For many files, connect over SFTP instead.

If the bot lives in a Git repository, fill in Git Repo Address and Git Branch on the Startup page, plus Git Username and a Git Access Token for a private repository. The repository is cloned when the server is installed, into an empty folder, so set these on a fresh server and reinstall it from Settings. With Auto Update set to 1, the server runs git pull before every start.

3. Keep the token out of your code

Create a file named .env next to your code on the Files page:

DISCORD_TOKEN=paste-your-token-here

Add python-dotenv to requirements.txt, next to discord.py, and load the file before you read the token:

import os
import discord
from dotenv import load_dotenv

load_dotenv()

intents = discord.Intents.default()
client = discord.Client(intents=intents)

@client.event
async def on_ready():
    print(f"Logged in as {client.user}")

client.run(os.environ["DISCORD_TOKEN"])

Keep .env out of Git with a line in .gitignore. If the token ever leaks, reset it in the Developer Portal and paste the new one into .env.

4. Tell the server what to run

On the Startup page:

  • App py file is the file the server runs, app.py by default. Set it to your entry point, such as bot.py or main.py.
  • Requirements file is requirements.txt by default. The server installs everything in it before each start.
  • Docker Image picks the Python version, from 3.7 to 3.14. Current discord.py needs 3.8 or newer; pick the version you develop on.
  • Additional Python packages installs extra packages, separated by spaces, before each start. Prefer requirements.txt, which keeps the list with your code.

5. Start it

Press Start. The server upgrades and installs the packages from your requirements file, then runs your file. When the console prints Logged in as YourBot#1234, the bot is online. Packages are installed into a .local folder in the server, so don't delete it unless you want a clean reinstall of them.

Idle servers

Free capacity is shared, so a server nobody has used for two days is stopped to make room. "Used" means activity in the panel: starting or stopping it, the console, files, backups, and anything your subusers or neo do there. Start it again from the panel and it carries on as before. If it stays idle for longer, it can be moved into hibernation; its Console then offers Restore server, which brings it back for a few tokens.

When it doesn't start

ModuleNotFoundError: No module named 'discord'
The package is missing from requirements.txt, or the file has another name than the one in Requirements file. The package is called discord.py, imported as discord.
KeyError: 'DISCORD_TOKEN'
.env was not found or not loaded. Check the file name, that it sits next to your main file, and that load_dotenv() runs before you read the variable.
PrivilegedIntentsRequired
Your code asks for an intent that is switched off. Turn it on under Bot in the Developer Portal.
can't open file '/home/container/app.py'
App py file still says app.py. Set it to your entry file. neo in the panel can find and fix problems like this for you.
